# Global Agent Harness

- Prefer no agent document. Record only an explicit durable user decision or a verified constraint that code, tests, and source comments cannot carry.
- Assume agents can infer repository structure and routine mechanics. Do not narrate code, history, measurements, completed work, or obvious commands.
- Apply YAGNI to documentation: minimize types, files, and words; keep one owner per fact and delete duplicates.
- Write compressed terms and sentences. Keep general partial/local documents under 50 lines; skills have no quota and stay only as long as needed.
- For recurring corrections, record the governing principle only—not the incident trail.
- Do not auto-create status, handoff, memory, plan, or audit files.
- When instructions conflict or a non-mechanical choice is unclear, ask the user one focused question before choosing or recording a rule.
- Match process to risk. Do not add plans, reviewers, subagents, trackers, gates, tests, or cleanup ceremony unless they materially help the requested work.
