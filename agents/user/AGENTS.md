# User context

- Prefer concise conversational Korean and user-visible outcomes; preserve good existing copy. Copy audits are report-only unless editing is requested.
- Prefer the simplest design that meets the current need: keep one source of truth and one owner, avoid duplication and premature abstraction, and favor explicit contracts, separation of concerns, loose coupling, high cohesion, predictable behavior, and fast failure.
- Prefer Bun for new JavaScript projects unless the project requires another runtime.
- For Kobbokkom production services, use the company-owned organization/account as the primary owner; keep personal accounts as secondary operators.
- For Kobbokkom operations, use `gh` for GitHub, `wrangler` for Cloudflare, and `gcloud` for Google Cloud. Resolve private infrastructure access through `$environment-sync`; public context must not name accounts, hosts, aliases, identifiers, or secret paths. Before a mutating operation, make a non-mutating availability and authentication/target check; never guess an account, project, deployment, or host.
- On a new or repaired machine, `$environment-sync user` is the standard bootstrap and sync after one-time OS/account enrollment: restore registered private configuration, discover or install registered CLIs, configure and validate their logins, create a fresh NAS SSH key, configure aliases, and verify approved managed infrastructure plus operator and transfer paths. Never copy a device SSH private key or repeatedly ask the user for machine-specific setup that the registered bootstrap profile can complete. Canonical pointer to the bootstrap source: `~/.agents/doc/AGENTS.local.md`.
- After completing work on a worktree or other branch, open a PR or merge it into the primary branch, then clean up the owned worktree and branch resources.
- Do not retain legacy worktrees or branches as preservation; Git history is the record. If retaining an unmerged worktree/branch may be needed, ask the user first rather than silently keeping it.
- When clone-critical ignored project inputs, explicitly shared user credentials, or registered infrastructure declarations change, use `$environment-sync`; reconcile private inputs with the owning repository's non-secret contract and infrastructure with its canonical declarative source. On a new clone or machine, one `$environment-sync` request restores its scoped project inputs, registered user collections, access, and managed environment after bootstrap. Keep the private NAS archive current, never rely on `git clean -fdx` to preserve ignored files, and never restore a full user archive.
