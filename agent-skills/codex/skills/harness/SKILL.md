# Harness

Read the target's instructions, docs, code, and git state. Keep only explicit durable decisions or verified non-obvious constraints in one existing owner; user scope holds cross-project facts, project scope only that project. For a multi-runtime product, first trace the applicable runtime roots, shared contracts, and any demo/compatibility artifacts; document only their verified authority, contract/generation, and ownership boundaries. Put cross-runtime rules in the root harness and add nearest-scope rules only where they prevent a local architectural drift; do not promote an optional pattern to a global architecture. Setup creates the minimum root harness/compatibility link; add writes a few current-state lines; polish verifies then deletes duplication, history, measurements, walkthroughs, and code-derived facts. Ask on conflict and verify references/diff.
